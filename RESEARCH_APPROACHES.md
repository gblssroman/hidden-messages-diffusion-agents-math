# Два основных подхода к общению диффузионных LLM

Основание: статья `48_Hidden_Messages_Between_Dif.pdf`, рисунок 1, §3.1–3.2, §4.1 и приложение A; реализация в репозитории.

- Общий метод: Hidden Messages — передача компактного скрытого состояния между независимыми агентами.
- Две основные реализации: **Tiny-A2D 0.6B — gated residual fusion** и **Dream-7B — virtual prefix**.
- Три экспериментальные постановки: HM-Synth Chain на Tiny; dependency spanning на Dream; distributed QASC на Dream.
- Каждый агент имеет свой приватный контекст и состояние генерации. Оценивается ответ агента 0.
- В обоих интерфейсах сообщение — четыре плотных вектора по 128 компонент в BF16.



## Подход 1. Сообщение добавляется перед LM head (Tiny-A2D 0.6B)

```text
Отправитель A:
  Контекст A + [MASK]
    -> Embeddings
    -> Transformer
    -> Скрытые состояния H_A
    -> Attention-компрессор
    -> Сообщение M [4 x 128]

Передача: A -> B, сообщение M.

Получатель B:
  Контекст B + [MASK]
    -> Embeddings
    -> Transformer
    -> Скрытое состояние ответа H_B
    -> Fusion(H_B, M)                  <-- ТОЧКА ДОБАВЛЕНИЯ
    -> H'_B = H_B + gate * delta
    -> LM head
    -> Ответ
```

- **Где вмешательство:** после трансформера, непосредственно перед выходной головой; изменяется состояние позиции ответа.
- **Что отправляется:** attention-компрессор сжимает скрытые состояния токенов отправителя до `4 × 128`.
- **Как принимается:** cross-attention извлекает информацию из сообщения; gated residual добавляет поправку к состоянию получателя.
- **Что обучается:** компрессор и fusion совместно; базовая модель и LM head заморожены. Используются учитель с объединённым контекстом и различение правильных/переставленных сообщений.
- **Фактический эксперимент:** HM-Synth Chain, один проход каждого агента с одним замаскированным ответом, передача 1 → 0.
- **Результат:** 2 000 примеров; 72,95% с правильным сообщением, 8,65% без сообщения.
- **Код:** [ReceiverChannel](code/scripts/phase5_hm_synth_tiny.py), [MessageCompressor](code/src/hidden_messages/communication/compressor.py), [MessageFusion](code/src/hidden_messages/communication/fusion.py).



## Подход 2. Сообщение добавляется как виртуальный входной префикс (Dream-7B)

```text
Отправитель A, текущий проход:
  Контекст A + состояние генерации
    -> Embeddings
    -> Transformer
    -> Скрытое состояние позиции ответа h_A
    -> MLP-encoder
    -> Сообщение M [4 x 128]

Передача: A -> B, сообщение M.

Получатель B, подготовка префикса:
  Сообщение M
    -> MLP-projector
    -> Виртуальный префикс P [4 x d_model]

Получатель B, следующий проход:
  Embeddings своего контекста и состояния генерации
    -> Вставка префикса P              <-- ТОЧКА ДОБАВЛЕНИЯ
    -> Transformer
    -> LM head
    -> Обновление генерации / ответ
```

- **Где вмешательство:** во входные embeddings, до первого слоя трансформера следующего прохода получателя.
- **Что отправляется:** MLP сжимает одно скрытое состояние позиции ответа в `4 × 128`.
- **Как принимается:** обучаемая проекция превращает сообщение в четыре виртуальных токена; масштаб согласуется с входными embeddings модели. В recurrent-режиме префикс сохраняется до замены.
- **Что обучается:** сначала encoder с вспомогательным классификатором и регуляризацией разнообразия; затем encoder замораживается и обучается projector префикса. При обучении канала backbone и LM head заморожены.
- **Источник:** [DenseLatentPrefixChannel](code/src/hidden_messages/communication/dense_latent_prefix.py).

### Подподход 2.1. Dependency spanning — запрос и ответ внутри диффузии

```text
Агент 0: знает запрошенный слот.
Агент 1: знает таблицу «слот -> код».

Шаг 2: агент 0 -> сообщение запроса -> префикс для агента 1
Шаг 3: агент 1 обрабатывает запрос с префиксом на входе
Шаг 4: агент 1 -> сообщение кода -> префикс для агента 0
Шаг 5 и далее: агент 0 использует префикс -> итоговый ответ
```

- **Обмен:** `0 → 1: запрос слота; 1 → 0: найденный код` происходит внутри диффузии. Второе сообщение зависит от первого.
- **Когда добавляется:** сообщения формируются на шагах 2 и 4, начинают влиять со следующего прохода; индексация с нуля. Префикс сохраняется между проходами.
- **Результат:** средняя точность 99,97% против 9,77% без сообщения, по 1 024 примерам в трёх повторах.
- **Код:** [persistent-prefix sampler](code/src/hidden_messages/diffusion/persistent_prefix.py), [проверка dependency spanning](code/scripts/verify_phase6_v15_dependency_span_confirmation.py).

### Подподход 2.2. QASC — объединение раздельных фактов

```text
Агент 0: вопрос + свой факт.
Агент 1: тот же вопрос + другой факт.

Recurrent:
  Проход обоих агентов -> сообщения M0 и M1
    -> M1 становится префиксом агента 0
    -> M0 становится префиксом агента 1
    -> следующий проход обоих агентов с префиксами
  Всего 4 раунда обмена -> финальный проход агента 0 -> ответ

Late-only:
  Независимый проход каждого агента
    -> сообщение агента 1 -> префикс агента 0
    -> финальный проход агента 0 -> ответ
```

- **QASC recurrent:** у каждого агента свой факт; четыре синхронных взаимных обмена, затем финальный проход агента 0. В реализации это повторные проходы с обновлёнными префиксами и неизменным `[MASK]`, без промежуточного раскрытия ответа. Точность 80,8% на 1 000 development-примерах.
- **QASC late-only:** независимая обработка приватных фактов, затем одно сообщение агента 1 и финальный проход агента 0. Точность 87,8%; без сообщения 72,6%.
- **Код:** [QASC](code/scripts/phase8_qasc_hiddenbench_dense_prefix.py).



**Как считать подходы**

- **Один общий метод:** Hidden Messages.
- **Два основных интерфейса:** residual fusion на Tiny и virtual prefix на Dream.
- **Три экспериментальные постановки:** Tiny HM-Synth, Dream dependency spanning, Dream QASC.
- Recurrent / late-only — расписания передачи. Zero / random / deranged / self / wrong-fact — контрольные условия.
- `InputPrefixChannel`, `SemanticPrototypeChannel` и промежуточные скрипты из кода не следует считать дополнительными основными подходами статьи.
